# HubSpot app project (CLI-managed)

This folder is a [HubSpot Developer Projects](https://developers.hubspot.com/docs/apps/developer-platform/build-apps/overview)
definition for the OAuth app this service connects to. It exists because,
as of the current HubSpot developer console, **creating a new public/OAuth
app through the classic UI ("Legacy Apps") is disabled** — HubSpot now
requires new OAuth apps to be created and managed through their CLI. This
is the exact config used to stand up the app for this project.

## What's here

- `hsproject.json` — project manifest (name, source dir, platform version).
- `src/app/app-hsmeta.json` — the app itself: OAuth config (redirect URL,
  scopes), distribution (`private` — installable only on your own account/test
  accounts, not published to the Marketplace).
- `src/app/webhooks/webhooks-hsmeta.json` — webhook subscriptions
  (contact/deal creation, property changes, deletion) and the target URL
  events get delivered to.

No secrets live in this folder — the Client ID/Secret are generated by
HubSpot when you deploy and only ever live in your local `.env` (see the
main [README](../README.md)).

## Using it

```bash
npm install -g @hubspot/cli

# Authenticate the CLI (get a Personal Access Key from your HubSpot
# developer account: Development > Keys > Personal Access Key)
hs account auth --pak <your-personal-access-key> --account <your-hub-id> --name my-hub --default

cd hubspot-app
hs project validate
hs project upload   # builds + deploys, creating the app in your account
```

Then, in your HubSpot developer account, go to **Development → Projects →
your project → the app component → Auth tab** to copy the **Client ID** and
**Client secret** into the main service's `.env`.

## Webhook target URL

`webhooks-hsmeta.json`'s `targetUrl` currently points at the live production
deployment (`https://hubspot-integration-service.vercel.app/webhooks/hubspot`)
— that's a real, permanent HTTPS endpoint, so webhook delivery works as-is,
no tunnel needed.

If you fork this and deploy your own instance, update `targetUrl` (HubSpot
requires **HTTPS** here — `http://localhost` is rejected at deploy time) to
your own deployed URL, or to a tunnel's URL for local testing (e.g.
`cloudflared tunnel --url http://localhost:3000`), then re-run
`hs project upload` to activate it.

The `redirectUrls` in `app-hsmeta.json` list both `localhost:3000` (for
local OAuth testing) and the production URL — keep both in sync with
whatever `HUBSPOT_REDIRECT_URI` your running instance actually uses.
